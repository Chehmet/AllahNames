# Асма · Имена Аллаха

Двуязычный учебный сайт на HTML, CSS и JavaScript. В каталоге 99 имён с арабским написанием, кириллицей, латинской транслитерацией, пояснениями и ассоциациями. Квиз перемешивает вопросы и варианты ответа. В карточках есть интервальное повторение, а в группах можно сравнить близкие значения и сразу начать тренировку.

## Опубликовать на GitHub Pages

1. Создай новый публичный репозиторий, например `asma-quiz`.
2. Загрузи **содержимое** папки проекта в корень репозитория. В репозитории должны быть видны `docs/` и `README.md`. Если пользуешься ZIP, сначала распакуй его.
3. В репозитории открой **Settings → Pages**. Выбери **Deploy from a branch**, ветку **main** и папку **/docs**. Нажми **Save**.
4. Открой опубликованный адрес вида `https://ТВОЙ-ЛОГИН.github.io/asma-quiz/`. Публикация может занять несколько минут.

Сольный квиз, карточки, каталог, группы и локальное избранное готовы к работе сразу после публикации. [Инструкция GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## Включить вход и общую игру

GitHub Pages отдаёт интерфейс. Supabase проверяет коды из писем, хранит облачное избранное и синхронизирует комнаты.

1. Создай проект Supabase. В **SQL Editor** выполни содержимое [supabase/schema.sql](supabase/schema.sql). Если Data API в проекте выключен, включи его для схемы `public`. Схема `asma_private` остаётся закрытой, а сайт вызывает только функции `aq_*`.
2. В **Authentication** включи провайдер **Email**, регистрацию новых пользователей и **Anonymous sign-ins** для игроков без аккаунта. В настройке **Site URL** укажи полный адрес GitHub Pages.
3. В **Authentication → Email Templates** добавь `{{ .Token }}` в шаблоны **Magic Link** и **Confirm Signup**. Пример тела обоих писем:

   ```html
   <h2>Код входа в Асма</h2>
   <p>Введи этот код на сайте: {{ .Token }}</p>
   ```

   Чтобы письма могли получать участники, чьи адреса не входят в команду проекта Supabase, подключи свой SMTP. Встроенная отправка годится для проверки на разрешённых адресах команды проекта. Если у группы общий Wi‑Fi, проверь лимит анонимных входов с одного IP. [Вход по коду](https://supabase.com/docs/guides/auth/auth-email-passwordless), [настройка SMTP](https://supabase.com/docs/guides/auth/auth-smtp), [анонимный вход](https://supabase.com/docs/guides/auth/auth-anonymous), [лимиты Auth](https://supabase.com/docs/guides/auth/rate-limits)
4. В [docs/config.js](docs/config.js) укажи **Project URL** и **Publishable key** (`sb_publishable_…`). Эти два значения предназначены для браузера. Храни secret key, service_role и пароли вне репозитория. [Ключи Supabase](https://supabase.com/docs/guides/getting-started/api-keys)
5. Загрузи обновлённый `docs/config.js` в репозиторий. После публикации проверь вход по почте и создай пробную комнату. На втором телефоне открой QR камерой или введи восьмизначный код комнаты вручную.

Ведущий входит по почте, создаёт комнату и открывает следующий вопрос после разбора. Игрокам достаточно ника. Правильный ответ приносит один балл, при равенстве баллов участники занимают одно место. После завершения доступны распределения по каждому варианту и таблица лидеров. Ведущий может скачать CSV с ответом каждого участника на каждый вопрос, включая пропуски. Проект хранит ники и ответы в Supabase. Срок доступа к активной комнате составляет 6 часов, к результатам — 7 дней. Для регулярной уборки можно периодически удалять в SQL Editor истёкшие комнаты командой `delete from asma_private.rooms where expires_at < now();`. Связанные игроки и ответы удаляются каскадно.

Избранное синхронизируется после входа. Сольная статистика и расписание повторений хранятся в текущем браузере.

## Запуск и проверки

Понадобится Node.js 22 или новее. Перейди в папку проекта и запусти:

```sh
npm start
```

Открой адрес, который напечатает команда. Для локального просмотра и GitHub Pages сборка и установка пакетов не нужны. Если PowerShell блокирует `npm.ps1`, используй `npm.cmd start`.

```sh
npm ci
npm test
```

Автотесты проверяют полноту карточек, случайную выборку, 50/50, интервалы повторения, декодирование QR, CSV, клиент входа и жизненный цикл комнаты на PostgreSQL через PGlite. Интеграционная проверка использует отдельные роли ведущего, игроков и постороннего пользователя.

Для локальной проверки игры после `npm ci` выполни `node tests/preview-cloud.mjs`. Две ссылки в терминале открывают ведущего и игрока в отдельных браузерных сессиях. Вход ведущего использует тестовый адрес `host@example.test` и код `112233`. Игрок вводит код комнаты вручную. Эта проверка использует временную базу и заменяет доставку писем. Доставка писем и подключение телефонов проверяются после публикации с подключённым Supabase.

## Редактирование карточек и источники

[docs/names.js](docs/names.js) хранит карточки, группы, пояснения, ассоциации и ссылки. Внутри этого файла порядок определяет ID, который сохраняется в избранном и результатах игр. Для обновления опубликованного каталога редактируй записи на своих местах.

Каталог следует традиционному перечислению у ат-Тирмизи 3507. Хадис аль-Бухари 2736 подтверждает сообщение о 99 именах без перечня. О происхождении перечисления у ат-Тирмизи есть хадисоведческое обсуждение, отмеченное в приложении. Каждая карточка даёт ссылки, а для косвенных свидетельств указывает контекст. Различия между близкими именами передают учебные акценты. Для повторной сверки 152 ссылок на аяты запусти `node tests/audit-sources.mjs` с подключением к интернету.
